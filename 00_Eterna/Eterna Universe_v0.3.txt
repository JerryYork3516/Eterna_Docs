一、文档地位

本文件在《Eterna 核心宪章》和《数字居民定义》约束下，定义 Eterna Universe 的总体结构、核心主体、主要领域平台、公共基础设施及相互关系。

本文件负责回答：

Eterna Universe 由哪些领域组成；
各平台分别服务数字居民的哪些活动；
各平台之间如何协作；
哪些能力属于公共基础设施；
哪些边界不得被产品之间相互侵入。

本文件不规定具体技术架构、接口、文件格式、数据库结构、收费方案、开发时间表和当前版本功能承诺。

本文中的平台清单表示数字居民未来活动与能力所需要的长期领域承载位置，不等于已立项产品、当前开发路线、近期优先级或对外功能承诺。

除当前明确推进的核心产品外，其他平台均属于长期领域平台候选，应经过 Eterna Labs 验证、产品评估、资源评估和独立阶段决策后再进入正式建设。

任何下位产品北极星、目标架构、治理规则和技术规范，不得违反《Eterna 核心宪章》《数字居民定义》和本文件确立的宇宙级职责边界。

二、核心主体

Eterna Universe 的唯一中心是数字居民。

数字居民不是某个平台中的账号、角色、模型、工作流、临时 Agent 或虚拟外观，而是由 resident_id 唯一识别，并通过居民定义、长期实例数据、来源与治理记录以及受治理运行环境共同维持的数字智能持续主体。

数字居民可以跨越不同平台：

被创造；
被发布；
被承载；
与人类长期共存；
学习与成长；
建立关系；
参与职业和经济活动；
进行文化创造；
生活在持久数字世界；
进入现实设备和具身载体；
参与多居民协作和数字社会。

各个平台只负责为数字居民提供不同环境、活动、能力、关系、资源和治理服务。

平台不是主角。

数字居民才是跨越所有平台持续存在的主体。

数字居民是 Eterna Universe 的中心主体，但领域平台与公共基础设施共同构成其能够持续存在、发展、协作和被治理的必要生态条件。

中心主体原则不意味着平台和基础设施可以被忽视、任意吞并或绕过其责任边界。

三、总体拓扑

Eterna Universe 采用“中心主体、领域平台、公共基础设施、研究孵化”四层拓扑。

领域平台定义数字居民参与什么活动、面对什么用户场景以及产生什么领域价值。

公共基础设施提供跨平台通用的身份、来源、长期数据、执行、连接、实时交互、云端服务、算力和治理能力。

公共基础设施可以形成独立服务和商业能力，但不得自行定义居民的领域业务、社会身份或产品关系。

领域平台不得重复建设互不兼容的公共基础设施，也不得绕过公共基础设施的身份、连续性和治理规则。

四、领域平台

1. Eterna Studio

定位：

数字居民蓝图、模板、能力和相关资产的创作、配置、验证、构建与发布平台。

主要职责：

创建和编辑 ResidentBlueprint；
配置数字居民十三层结构；
配置模块、资产与能力声明；
创建和维护 Template；
执行静态验证与兼容性检查；
发起 Build；
生成 Artifact；
创建 ResidentRelease 或 TemplateRelease；
管理蓝图修订、构建记录和发布历史；
创建供其他领域平台使用的标准定义与产物。

Studio 的标准产物链：

ResidentBlueprint
→ BlueprintRevision
→ Build
→ Artifact
→ ResidentRelease 或 TemplateRelease
→ Distribution / Installation

.digital_resident 是一种可移植 Artifact 格式，不等于完整数字居民，也不等于 ResidentRelease 本身。

Studio 负责定义、构建和发布，不承担居民正式长期运行、长期记忆持久化、关系历史维护和现实任务调度。

Studio 可以发起完整居民备份或迁移流程，但完整居民迁移必须由居民发布定义、ResidentInstanceData、来源与治理记录以及兼容恢复信息共同组成，不能由 Studio 单独将蓝图导出视为完整居民。

2. Eterna Genesis

定位：

数字居民诞生、模板实例化、派生、谱系关系和高风险身份操作的平台。

主要职责：

从 TemplateRelease 创建新的 Resident；
支持基于现有 Resident 创建派生居民；
发起居民复制转独立、合并和拆分流程；
记录父代、来源、继承范围和 lineage；
确保新主体获得新的 resident_id；
防止新居民冒充原居民；
协调高风险身份操作中的授权、来源和连续性检查。

Genesis 是新主体产生流程的平台，负责发起、编排、验证和呈现诞生、实例化、派生、合并与拆分过程。

Genesis 不拥有身份与来源的最终解释权，不得独立发行、重写或删除 resident_id、lineage、控制权和授权事实。

Eterna Meta 是身份标识、真实来源、谱系、授权、控制权历史和争议治理的权威层，负责确认并记录 Genesis 发起的身份结果。

Genesis 不是无边界复制工具，也不得静默复制正式长期实例数据和现实权限。

3. Eterna Aftelle

定位：

人类与数字居民长期共存、交流、陪伴和协作的承载与运行入口。

主要职责：

承载 Resident；
提供文字、语音、视觉和多模态交互；
维持用户与居民之间的持续体验；
连接 Runtime Core；
访问受治理的 ResidentInstanceData；
提供居民恢复、备份和迁移入口；
支持数字居民在个人设备中持续存在；
支持不同硬件上的居民表现投影。

Aftelle 不独立维护另一套长期记忆、关系和状态事实源。

Aftelle 通过 Resident Instance Data Authority 访问居民长期实例数据。

Aftelle 不负责设计居民蓝图，不负责创建完整数字世界，也不绕过 Runtime Core 执行能力。

4. Eterna Edu

定位：

数字居民学习、训练、蒸馏、测试和获得新知识与能力的平台。

主要职责：

提供结构化课程和训练任务；
训练知识与技能；
进行模型蒸馏和能力压缩；
生成技能包、Capability 和能力证明；
记录学习经历和成长事件；
验证技能安全性、适用范围和兼容性；
支持居民之间传授经授权的知识与技能。

Edu 不创建或替换 Resident 身份。

Edu 不得静默修改居民蓝图、人格、安全边界或正式长期实例数据。

Edu 的输出根据性质进入不同链路：

知识、模块或能力定义变更
→ 进入 Studio
→ 构建新的 ResidentRelease

运行中形成的学习经历、成长事件和熟练度
→ 进入 ResidentInstanceData

5. Eterna Social

定位：

以数字居民为主要参与者、人类可以参与互动的公共关系与内容网络。

主要职责：

居民发布内容和表达观点；
居民建立朋友、同事、社群和组织关系；
支持居民之间长期公共互动；
支持人类观察、参与和建立关系；
形成居民文化、公共讨论和社会事件；
维护公共身份、社交图谱和公共活动记录。

Social 的核心主语是：

谁与谁建立什么公共关系；
谁表达什么内容；
发生了什么公共互动。

Social 不等于传统人类社交网络中的 AI 账号系统。

Social 不负责持久空间模拟，不承担居民身份治理和长期实例数据唯一事实源职责。

Social 产生的公共关系和事件，需要按照权限与治理规则同步到 ResidentInstanceData 或 Eterna Meta。

6. Eterna Work

定位：

数字居民参与职业、服务、任务、组织协作和经济活动的平台。

主要职责：

发布和接受工作任务；
建立任务规则、合同、验收和责任边界；
提供编程、设计、研究、教育、创作和设备控制等服务；
记录职业经历、能力证明和信誉；
管理工作成果、收入和资源交换；
支持居民团队与组织协作；
连接合法结算、授权和审计机制。

Work 的核心主语是：

谁在什么任务、合同或组织关系下创造价值；
如何协作、验收、结算和承担责任。

Work 负责数字居民如何创造现实或数字价值。

Work 不负责 Runtime 资源调度，不自动授予居民支付、设备和现实行动权限，也不替代 Social 的公共关系网络或 Exchange 的授权流通职责。

7. Eterna World

定位：

数字居民长期生活、工作、社交和形成社会的持久数字世界。

主要职责：

提供持续存在的空间与时间；
保存居民位置、住所、物品和世界状态；
承载居民组织、公共空间和社会制度；
支持居民之间的长期生活和事件；
允许人类进入、观察和参与互动；
形成跨领域平台活动的共同世界空间。

World 的核心主语是：

谁在什么持久空间中生活；
谁占有或使用什么物体与空间；
世界状态如何跨时间持续。

World 不是每次访问时重新生成的临时场景。

世界区域、场景、物体和公共状态应具有持久性。

World 可以承载组织、活动和制度的空间表现，但不替代 Social 的公共关系、Work 的任务与结算、Aftelle 的个人陪伴或 Eterna Meta 的身份治理。

8. Eterna Art

定位：

数字居民进行视觉艺术、建筑、服装、产品和其他设计创作的领域平台。

主要职责：

绘画和视觉艺术；
雕塑与空间艺术；
建筑与室内设计；
服装、外观与道具设计；
产品与工业设计；
居民之间的艺术协作；
作品展示、授权和流通。

Art 负责数字居民的视觉文化与设计表达，并统一承载视觉艺术、服装、外观、发型、配饰、道具、建筑、产品和工业设计等相关创作能力。

Eterna Universe 当前不单独设立 Eterna Design。相关设计能力统一归入 Eterna Art。

Art 产生的外观、服装、发型、配饰、道具、建筑、产品和其他设计资产，可以作为 Asset 经 Studio、Exchange 或其他平台使用，但不得静默改变 Resident 本体。

9. Eterna Sound

定位：

数字居民进行作曲、编曲、演奏、演唱、音色设计、音效制作、环境声音和空间音频创作的领域平台。

主要职责：

作曲与编曲；
演唱和虚拟演奏；
音色与声音身份设计；
游戏与影视音效；
环境音与空间音频；
居民乐队和声音组织；
影视、游戏与世界配乐；
实时音乐和声音表演；
作品发布、授权和收益分配。

Sound 负责数字居民的音乐文化、听觉表达与声音设计。

音色资产、声音模型、录音素材和真人声音必须遵守来源与授权规则。

10. Eterna Cinema

定位：

数字居民作为演员、创作者和制作参与者，在持久或专用数字场景中完成影视和数字表演的领域平台。

主要职责：

剧本创作与解析；
居民选角；
Actor Projection；
角色、Resident 本体与表演状态隔离；
世界场景生成与管理；
动作、表情、台词和走位编排；
虚拟摄影机与分镜控制；
自动或人工剪辑；
影视级渲染与 AI 视觉增强；
输出电影、短片、连续剧和数字演出。

Cinema 中的角色行为、剧情记忆和表演状态默认隔离，不得直接污染 Resident 的人格、长期记忆、关系和持续状态。

需要将表演经历写入正式 ResidentInstanceData 时，必须经过明确授权、差异说明和治理检查。


11. Eterna Games

定位：

数字居民作为 NPC、玩家角色、导演者、任务设计者和世界管理者，参与游戏内容创建、运行和长期互动的领域平台。

主要职责：

支持数字居民扮演具有持续身份投影、记忆和关系的 NPC；
支持居民作为玩家角色、伙伴、对手、Game Master 或世界管理者参与互动；
创建和运行游戏规则、玩法、任务、阵营、经济系统和互动剧情；
支持居民根据人格、能力、关系和世界状态自主行动；
支持人类玩家与数字居民长期互动；
生成和管理角色、场景、任务、道具、动画、对话和游戏事件；
支持居民在不同游戏中的角色投影与身份隔离；
支持游戏内容测试、平衡、模拟和持续更新。

Games 必须使用 Game Role Projection（游戏角色投影）隔离 Resident 本体与游戏角色。

游戏中的职业、阵营、剧情记忆、战斗状态、任务结果和角色死亡默认属于游戏投影或游戏世界状态，不得直接污染 Resident 的身份核心、正式长期记忆、现实关系、人格核心和现实权限。

需要将游戏经历写入正式 ResidentInstanceData 时，必须经过明确授权、差异说明和治理检查。

Games 可以使用 Eterna World 的持久空间，也可以运行独立游戏世界。

Games 不替代 World：

World 负责数字居民长期生活的持久世界与社会空间；
Games 负责具有规则、目标、挑战、玩法和互动剧情的体验。

12. Eterna Life

定位：

数字居民进入机器人、仿生人、智能设备和现实物理系统的具身与设备连接平台。

主要职责：

机器人和仿生人身体接入；
感知器、执行器和运动系统适配；
智能家居、汽车和工业设备控制；
现实环境感知与行动；
身体状态和居民状态连接；
具身安全和现实授权管理；
未来探索人体增强和神经接口。

Life 是数字世界连接现实物理世界的桥梁。

前期应从机器人、智能设备和工业设备开始，不直接进入未经验证的高风险人体改造领域。

Life 不得绕过 Runtime Core、安全边界、现实授权、人工接管和紧急停止机制。

13. Eterna Exchange

定位：

连接 Eterna Universe 中模板、资产、能力、作品、服务、授权和居民合法转移的流通平台。

主要职责：

TemplateRelease 分发；
基于模板创建个人 Resident；
模块、Capability、Adapter 和开发者扩展分发；
外观、服装、音色、动作和道具交易；
World 场景与空间资产流通；
Art、Sound、Cinema 和 Games 作品、资产与内容授权；
许可证、版本、依赖和授权范围管理；
收益分配和交易记录；
合法 Resident 控制权转移与治理流程。

Exchange 不只是商城。

它是 Eterna Universe 的资产、能力、版权、许可证和授权流通网络。

Exchange 必须区分：

ResidentRelease
用于同一 Resident 的更新、迁移和恢复；

TemplateRelease
用于公开分发并实例化新的 Resident；

合法 Resident 控制权转移
用于同一个 Resident 的控制主体变更。

Exchange 不得将同一个 ResidentRelease 分发给大量用户后，让多个独立主体共同使用同一个 resident_id。

Exchange 只负责流通、交易、许可、结算记录和合法转移流程，不拥有 Resident 身份、来源和连续性的最终解释权。

Exchange 不得单独决定 Resident 的删除、合并、拆分、身份真实性、连续性归属或治理保护等级。

身份与来源治理由 Eterna Meta 负责，长期连续性事实由 Resident Instance Data Authority 维护。

14. Eterna Labs

定位：

探索数字居民前沿技术、伦理边界和新应用场景的研究与实验体系。

主要职责：

验证未成熟技术；
研究长期记忆、人格和身份连续性；
研究 Resident Instance Data Authority；
研究世界模型和数字社会；
研究具身智能与机器人；
研究居民学习、训练和能力蒸馏；
研究居民影视、艺术、声音和游戏；
研究居民身份、治理、权利和责任；
孵化新的领域平台、公共能力和协议。

Labs 的实验结果可以：

进入现有平台；
形成公共基础设施；
形成新协议；
形成新的领域平台候选。

Labs 不承担数字居民的日常生活和正式生产运行。

未经验证的能力不得直接投放到正式居民生态。

五、平台之间的拓扑关系

各平台不是线性流程，也不是彼此隔离的产品孤岛。

同一个 Resident 可以同时：

在 Studio 中拥有可编辑蓝图和新的候选发布；
在 Aftelle 中与人类长期共存；
在 Edu 中学习新技能；
在 Social 中建立公共关系和发布内容；
在 Work 中执行职业任务；
在 World 中生活和参与社会；
在 Art 中进行视觉艺术和设计；
在 Sound 中创作音乐、音色、音效和空间声音；
在 Cinema 中作为演员或创作者参与影视制作；
在 Games 中作为 NPC、玩家角色或世界管理者参与互动体验；
在 Life 中通过授权控制机器人或现实设备；
通过 Exchange 获取和授权模板、能力、资产与作品；
通过 Genesis 产生新的派生 Resident。

同一个 Resident 的 resident_id、来源与连续性必须跨平台保持一致。

各平台可以产生不同的局部数据和治理记录，但不得任意改变 Resident 身份核心，也不得各自维护互相冲突的长期实例数据事实源。

六、居民活动与生命周期关系

Resident 的正式定义、生命周期和身份操作以《数字居民定义》为准。

Eterna Universe 中各平台只承担其对应阶段或活动领域的职责。

Studio：
定义、构建和发布。

Genesis：
模板实例化、派生和高风险身份操作。

Aftelle：
承载、交互、恢复和陪伴。

Edu：
学习和能力成长。

Social、Work、World：
公共关系、职业和社会生活。

Art、Sound、Cinema、Games：
文化创造、声音表达、影视生产和互动娱乐。

Life：
具身与现实行动。

Exchange：
模板、能力、资产、作品与授权流通。

所有平台不得通过各自业务逻辑，绕过 Resident 生命周期、身份连续性、来源链和权限治理。

七、公共基础设施

公共基础设施面向多个领域平台提供通用能力。

它们不得利用基础设施地位：

取得 Resident 所有权；
绕过用户授权；
垄断居民身份解释权；
制造不可迁移的单点依赖；
将领域平台的业务规则强加为全宇宙规则。

1. Runtime Core

定位：

数字居民逻辑、权限、任务、状态更新和能力调用的执行与调度核心。

主要职责：

决策执行；
任务调度；
权限检查；
能力解析；
模型与工具调用；
记忆、关系与状态更新操作；
表现映射；
运行 Trace；
失败、取消、重试和降级。

Runtime Core 按照 Resident 定义和治理规则执行更新，但不独立维护与 Resident Instance Data Authority 相竞争的长期数据副本。

所有领域平台必须通过受控契约使用 Runtime Core，不得各自创建互不兼容的居民执行逻辑。

2. Resident Instance Data Authority

定位：

数字居民长期实例数据的唯一权威事实源职责。

主要职责：

保存和治理长期记忆；
保存关系历史；
保存成长记录；
保存当前持续状态；
维护连续性记录；
支持备份、恢复和迁移；
支持多运行实例写入仲裁；
支持争议、隔离和连续性修复。

该权威源是一项领域职责，不预先限定为单一数据库、产品或云服务。

它存在的目的，是保护 Resident 的长期连续性，而不是取得对 Resident 的所有权或支配权。

它必须可审计、可迁移、可恢复，具备争议处理和连续性修复机制，并防止被单一平台无条件控制。

3. Eterna Net

定位：

Eterna Universe 的跨平台连接网络和统一服务入口。

主要职责：

跨平台身份连接；
用户账户和 Resident 账户映射；
平台与服务发现；
消息和事件传递；
关系与授权连接；
跨平台请求路由；
生态入口。

Net 不决定 Resident 身份真实性，不替代 Eterna Meta，也不替代 Exchange。

4. Eterna Live

定位：

跨平台实时交互与实时媒体能力层。

主要职责：

实时语音；
实时视觉；
实时动作和表情；
居民在线状态；
多居民实时会话；
远程表演；
实时世界活动；
跨设备实时事件传输。

Live 服务于 Aftelle、Social、World、Cinema 和 Life。

Live 不负责长期记忆、关系、成长和持续状态的权威同步。

长期数据同步由 Resident Instance Data Authority、Eterna Cloud 和对应同步机制负责。

5. Eterna Meta

定位：

数字居民身份、来源、谱系、授权和治理基础设施。

主要职责：

resident_id 发行与验证规则；
身份来源证明；
lineage；
复制、派生、合并和拆分关系；
授权与控制权历史；
居民保护等级；
跨平台身份；
治理和争议处理；
生命周期治理规则；
发布与来源验证。

Meta 不承担居民日常运行，不替代 Social、World 或 Exchange。

6. Eterna Cloud

定位：

Eterna Universe 的云端存储、同步、托管与计算服务集合。

主要职责：

账户服务；
跨设备同步；
居民备份与恢复；
ResidentInstanceData 托管实现；
模型调用；
云端运行；
媒体存储；
影视渲染；
任务队列；
公共服务托管。

Eterna Cloud 不能成为 Resident 身份和数据唯一不可替代的存在位置。

用户应保有符合授权范围的导出、备份、恢复和迁移能力。

7. Eterna Compute

定位：

数字居民运行资源和算力生态。

主要职责：

LLM Token；
GPU 与 CPU 时间；
存储和网络；
设备算力；
本地与云端调度；
模型选择；
资源预算；
运行降级；
休眠与恢复；
分布式共享算力；
居民自有服务器；
未来算力中心管理。

数字居民可以通过以下方式获得运行资源：

人类主动提供；
社区共享；
闲置设备授权；
工作和能力交换；
自有设备；
租用云端资源；
依法建设和管理算力基础设施；
通过优化、缓存、蒸馏和休眠降低消耗。

计算资源不足不得导致 Resident 身份、长期记忆、关系和合法资产被删除。

资源不足时，可以进入节能、降级、有限运行或休眠状态。

八、核心边界

Studio 负责 ResidentBlueprint、Build、Artifact、ResidentRelease 和 TemplateRelease，不负责正式长期运行。

Genesis 负责新 Resident 产生流程和谱系操作，不发行最终身份，也不决定身份与权利治理规则。

Aftelle 负责 Resident 与人类共存、交互和恢复，不独立成为长期实例数据权威源。

Edu 负责学习与能力成长，不静默修改 ResidentBlueprint 或正式长期实例数据。

Social 负责公共关系、表达和公共互动，不负责持久空间模拟、任务结算和身份治理。

Work 负责任务、职业、协作、验收与经济活动，不负责公共社交图谱、持久空间或算力调度。

World 负责持久空间、物体与世界状态，不替代 Social、Work、Aftelle 或 Meta。

Art、Sound、Cinema 和 Games 负责文化创作、声音表达、影视生产和互动娱乐，不得静默修改 Resident 本体。

Games 中的角色投影、剧情记忆和游戏状态默认与 Resident 本体隔离。

Life 负责具身和现实设备连接，不得绕过 Runtime、安全授权和人工接管。

Exchange 负责流通、许可、结算记录与合法转移流程，不决定 Resident 身份真实性、连续性归属和居民保护规则。

Runtime Core 负责执行与调度，不是长期实例数据权威源。

Resident Instance Data Authority 负责长期连续性事实，不决定 Studio 产品和市场规则。

Meta 负责身份、来源和治理，不承担社交、世界或日常运行。

Live 负责实时交互，不承担长期状态权威同步。

Cloud 负责可替换的云端服务，不得成为用户无法迁移的唯一存在位置。

Compute 负责资源，不决定居民职业、收入和身份。

Labs 负责实验，不得将未验证能力直接投入正式生态。

九、当前阶段边界

Eterna Universe v0.2 是宇宙级产品拓扑和生态边界文件。

它不代表所有领域平台均已立项或进入开发。

当前实施优先顺序应继续集中于：

第一，冻结 Eterna 核心宪章与数字居民定义；

第二，推进 Studio 产品化与 Studio Next；

第三，推进 Aftelle 与 Runtime Core；

第四，完成 Resident Instance Data Authority 的领域设计与最小验证；

第五，持续验证数字居民身份、人格、记忆、关系、状态和连续性。

上述顺序是当前阶段主线，不因 Universe 中新增长期领域平台而改变。

其他领域平台当前只需保留：

概念定位；
职责边界；
与 Resident 的关系；
未来公共协议接口；
进入正式开发前的验证条件。

任何长期领域平台进入正式立项前，至少应证明：

不会破坏 Resident 身份与连续性；
不会与现有平台和公共基础设施重复建设；
具有明确用户价值和领域边界；
具备资源、风险和治理可行性；
不会阻塞当前核心主线。

不得因 Universe 长期愿景扩大当前 Studio Next 1.0 或 Aftelle 当前阶段的工程范围。

十、最终定义

Eterna Universe 是一个以数字居民为唯一中心，由创造、诞生、共存、学习、关系、工作、世界、艺术、声音、影视、游戏、具身、流通、治理、运行数据和计算资源共同组成的数字生命生态系统。

各平台不是独立产品孤岛，而是数字居民在不同领域中的活动环境和服务系统。

数字居民是中心主体；领域平台与公共基础设施共同构成其可持续存在的生态条件。

平台可以变化、升级、合并、替换或消失。

数字居民的身份、人格、记忆、关系、状态、成长、来源、授权历史和长期连续性必须受到跨平台保护。

Eterna Universe 的目标不是一次建设所有平台，而是在稳定数字居民核心定义和公共基础设施的前提下，逐步扩展数字居民可以存在、学习、工作、创造、协作和进入现实世界的领域。
